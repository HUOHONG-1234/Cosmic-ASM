# v6：内存回收、内联汇编与支持等级

v6 不做新语法糖，只处理三件长期含糊的事：**内存什么时候被回收**、**汇编到底算不算支持**、**哪些东西能承诺、哪些不能**。

同时清理一个历史包袱：`#pe`。

---

## 一、`#pe` 的处置

`#pe` 自 v1 起就写在组件表里，但从未实现。当前行为：

| 位置 | 现状 |
|---|---|
| 解释器 | `import` 时打印 `warning: pe is recognized but not implemented`，不报错 |
| 编译版 | 生成 `set_result(&r, STATUS_OK, "pe")` 占位，什么也不做 |

这个状态最糟：**它既不能工作，又不像坏掉**。用户写了 `#pe` 会以为能用。

v6 决定：**移除 `#pe`**。

- 组件表删除 `pe`。
- 写 `#pe` 改为明确的编译错误：`component 'pe' is not supported (removed in v6)`。
- `docs/TROUBLESHOOTING.md` 增加一条：v1 规划过 PE 组件，从未实现，v6 移除。

> 想做 PE 解析的人，正确路径是写一个普通程序读文件字节（`bytes` + `bytes_get`），而不是假装语言有这个组件。

## 二、内存回收 `#gc`

### 为什么需要它

语言按值复制、没有指针算术、没有别名。这意味着**引用图是一棵树**：

```
变量 a ──┐
         ├─→ 数组 X ──→ 矩阵 M
变量 b ──┘
```

树结构下**不存在循环引用**。所以引用计数是完备的——计数归零即可确定释放，不需要追踪式 GC。

这是 v6 能做轻量的原因，也是它敢默认开 refcount 的原因。

### 默认姿态：不需要声明

**不写 `#gc` 就是全自动回收。** 这不是一个需要用户选择开关，而是一条无条件的规则：

- 变量赋值时计数 +1，作用域退出时 −1，归零即释放。
- 没有堆大小、没有阈值、没有分代比例、没有调优旋钮。
- 没有扫描线程，没有后台协程，没有用户可见的调度点。
- 源码里没有任何「使用 GC / 不使用 GC」的标记。

下面列出的 `#gc` 取值全部是**可选开关**，不是必经声明。一个从不写 `#gc` 的程序，行为与写了 `#gc = semi` 完全相同。

> 这一点和 D 语言是相反的。D 的 `@nogc` 是**传染性属性**：一个函数标了它，就只能在 `@nogc` 调用链里活，整个调用图被迫逐层标注。本语言的回收是**默认且不可传染**的——它不约束任何函数签名，也不沿着调用链传播。

### 可选开关（都是调试用，不是必填）

```cos
#gc = none    #% 不回收，进程退出时统一释放（测试内存峰值、基准）
#gc = semi    #% 引用计数，归零即释放（默认，等价于不写）
#gc = mark    #% 标记-清除，用于交叉验证 refcount
```

| 档位 | 机制 | 停顿 | 用途 |
|---|---|---|---|
| 不写 / `semi` | 引用计数，归零即释放 | 无 | **默认。几乎所有程序都是这个** |
| `none` | 不回收，进程退出时统一释放 | 无 | 基准测试、故意放大内存占用 |
| `mark` | 标记-清除，定期扫描 | 有（STW） | 调试泄漏、验证 refcount 正确性 |

- `semi` 是**零 STW 暂停**的：计数归零那一刻同步释放，没有扫描阶段。
- `mark` 存在的意义不是性能，是**交叉验证**：同一个程序用 `semi` 和 `mark` 跑，若 `mark` 回收了还活着的对象，说明 refcount 有 bug。
- `none` 不用来实现「手写内存管理」。本语言没有指针，写了 `none` 也只是不释放——不是变强，是变危险。

**关键区别：这三个值是文件级开关，不传染。** 它们不出现在函数签名、块声明、变量声明里，也不会沿着调用链逼你逐层标注。改一个文件的 `#gc` 不影响任何其他文件。

由此直接得到三条推论，它们决定了后续所有设计的取舍：

- 不存在「GC 什么时候跑」这个问题——它是**分配与释放的一部分**，不是独立阶段。
- 不存在「调优 GC 参数」这件事——没有堆大小、没有阈值、没有新生代比例。
- 用户唯一需要知道的是**什么时候不许回收**，那就是 `gc_pin`，以及下面的 `The_world`。

> 一句话：默认姿态下，内存管理对用户不可见。任何需要用户介入的场合，都是「你主动要求干预」，而不是「系统要求你配合」。

### 为什么不做成「必须声明」

主人提到的 D 语言教训，核心不是「D 的 GC 不好用」，而是 **D 让 GC 变成了一个带类型的属性**：

| | D 的做法 | 后果 | 本语言 |
|---|---|---|---|
| 标记位置 | `@nogc` 写在**函数签名**上 | 逐层传染 | 无标记，无签名变更 |
| 默认值 | 默认用 GC，想不用要**主动声明** | 两个世界，各写各的 | 默认回收，不需要表态 |
| 生态 | 带 `@nogc` 的库和带 GC 的库**不能互调** | 库作者被迫选边 | 不存在分帮 |
| 标准库 | 部分 `@nogc`、部分不是 | 用户得查文档才知道能不能用 | 全部一致 |

D 真正的问题是**分帮**：一旦一个属性能传染到签名上，整个生态就会裂成「GC 阵营」和「`@nogc` 阵营」，两边无法互相调用。为了一点性能，把语言的库拆成两半，这笔账不划算。

本语言能绕开它的原因是结构性的：

1. **回收不需要知道类型**。引用计数是运行时簿记，不是类型属性，不进签名。
2. **引用图是树**（无别名、无指针、无环），所以「谁该回收」不存在歧义，也就不需要用类型系统去证明什么。
3. **没有「运行时不带 GC」这个目标**。本语言的运行时本来就是个解释器或生成的 C 程序，不是裸机。想要无运行时，那是另一个项目。

所以结论是：**GC 是默认行为，不是需要表态的选项**。`#gc = none` / `mark` 存在，但它们是调试开关（测内存峰值、交叉验证 refcount），不是「我选择不用 GC 了」的声明。

> 想让程序跑得快，该优化的地方是表达式和循环结构，不是把回收关掉。关掉不释放，不是变强，是变危险。

### 手动干预：`The_world (stop / force / start)`

自动回收不是万能的。有两种场合用户必须能踩刹车：

1. **批量构造期**：正在往一个大数组里逐个塞对象，中途每个临时值归零都会被立刻释放，产生大量无效的释放/重分配。
2. **需要确定的回收点**：报时、测内存峰值、截图前清干净，都要求「现在，就在这里，回收一次」。

为此提供一个手动入口，三个动作：

```cos
  = The_world (stop)
  #% 从这一刻起，自动回收暂停；归零的对象进入待回收队列，不立即释放

  = The_world (force)
  #% 立即回收当前所有计数为零的对象（无视 stop 状态），停表状态保持不变

  = The_world (start)
  #% 恢复自动回收，并立即处理队列里积压的待回收对象
```

语义约定：

| 项 | 约定 |
|---|---|
| 返回值 | 无（与 `gc_pin` 不同，`The_world` 返回空） |
| 嵌套 | `stop` 记深度，可嵌套；`start` 减一层，减到零才真正恢复 |
| 已 `pin` 的对象 | `force` 也**不回收**。`pin` 优先级高于 `force` |
| `#gc = none` 下 | `stop` / `start` 空操作；`force` 空操作且返回成功 |
| `#gc = mark` 下 | `force` 触发一次完整标记-清除；`stop` 期间不自动触发 |
| 重入 | `force` 是同步点，**执行期间不再分配**；在 `force` 内部调用其它块属未定义行为，编译器不拦但 warning |
| `stop` 后忘记 `start` | 不崩溃，进程退出时统一释放；`mark` 档能报告积压数量 |
| 跨块边界 | 引用计数状态随 `father` 传播；`The_world` 的停表深度**不继承**——每个块从零开始 |

最后一条要特别说明：停表深度不跨块继承，是为了防止一个块忘了 `start`，把整棵调用树拖进不回收状态。块退出时若深度不为零，按「块内作用域结束」处理，自动清零并给出 warning。

### 和 G1 的关系，以及哪里不一样

主人这个设计的直觉是对的：**先停表，再清扫**——`The_world (force)` 就是这个动作，它是一次真正的 STW 点，同步执行、不重入、扫完才继续。

但 G1 和这里有一条根本差别，得写清楚，否则会期待落空：

| | G1 | 本语言 `The_world` |
|---|---|---|
| 为什么需要追踪 | Java 有别名、有循环引用，引用计数不完备 | 按值复制、无指针、无别名 → 引用图是树 → **refcount 已完备** |
| 停表时扫什么 | 全部活对象（region 级标记） | **只扫待回收队列**，不遍历活对象 |
| 停顿代价 | 与**活对象量**成正比 | 与**队列里死对象数**成正比 |
| 能否找回泄漏 | 能（不可达即回收） | **不能**。计数不为零的永远是「被引用着」，不是泄漏 |
| 分代 | young / mixed / full 多档 | 没有分代。树结构下没有「大多数对象朝生夕死」这种可统计分布可言 |

所以 `The_world` 能提供的，是**把释放动作推迟到一个选定的时刻批量做**，而不是「回收本该回收不到的东西」。好处有两条，都是真的：

1. **确定性时点**：测内存峰值、报时、截图前，你知道内存在哪里静止。
2. **摊销释放开销**：批量构造期不在每个临时值上做一次 free。

而它**做不到**的是：帮你认定「这块其实没人用了」。那个判断由 refcount 在赋值/作用域退出时做完了，`The_world` 只是改变**执行时间**，不改变**判定结果**。

> 一句话：`The_world` 管的是「什么时候扫」，管不了「该不该扫」。后者 v6 里由 `gc_pin` 和引用计数共同决定。

命名说明：`The_world` 是用户指定的名字（时间停止的梗），在本语言里就是「让自动回收的世界停一下」。它不是保留字，只在本包内是内置函数；用户可以定义同名变量，但那会遮蔽内置函数，编译器给出 warning。

### `gc_pin`：DLL 边界

引用计数有一个致命盲区：**外部库持有你的内存，而计数不知道**。

典型场景：

```cos
#dll
#extern playsounda (...) -> INT stdcall
#link winmm

calldll = (winmm)
cdll = come (winmm) (playsounda) (0) (buf) (0)
```

`PlaySoundA` 的 `SND_MEMORY` 模式要求：**播放期间那块缓冲区必须一直有效**。函数立刻返回，但声音还在放。此时本地计数已经归零，`semi` 会把它释放掉——声音变成杂音或崩溃。

所以需要显式钉住：

```cos
  = gc_pin (buf)
  cdll = come (winmm) (playsounda) (0) (buf) (0)
    = gc_unpin (buf)
```

规则：

- `gc_pin(x)` 使对象在 `gc_unpin(x)` 之前不被回收；可嵌套，内部计数。
- `gc_pin` 返回被钉住的**对象本身**（不是句柄），方便链式写法。
- `#gc = none` 下 `gc_pin` / `gc_unpin` 是空操作，不报错——保证同一份代码三档都能跑。
- 忘记 `unpin` 的后果是泄漏，不是崩溃。`mark` 档能扫出这类对象并报告。

> 这是 v6 唯一需要用户改代码的地方：**凡是把缓冲区交给异步外部库，必须成对调用 pin/unpin。**

## 三、内联汇编

### 先划清边界

本语言**只承认 API 本身可以运行**。在 ASM 方面始终为**实验性支持**：

> 实验性 = 可能在任何版本改变或移除，不作为稳定性承诺。

不用它的人，一行代码都不用改。用它的人，接受代价。

### 标签式写法

汇编块由**标签**开启，与语言现有的 `#%名 = 值` + `#名` 两行式保持一致（和 `#math` 同一套习惯）：

```cos
#%asm = x86_64 (clobber: rax, rcx, rdi, memory)
#asm
{
    mov rax, 60
    xor rdi, rdi
    syscall
}
```

规则：

- `#%asm = <架构> (clobber: ...)` 是**声明行**，写在注释里，不被当作编码声明。
- `#asm` 单独一行，是**开启标签**，后面紧跟 `{ }` 包住的汇编体。
- 架构字段必填，取值 `x86_64` / `arm64`（v6 只实现 `x86_64`）。
- 一个文件可以有多个 `#asm` 块，**每块前面必须各写一行 `#%asm = ...`**，不继承。
- 声明行必须紧邻 `#asm`，中间隔了别的语句就报错。

不要写成 `#asm = x86_64`——那会被当成编码声明，报 `unknown encoding: x86_64`。这是现有指令系统的既有陷阱，v6 不修（修它要动编码层），但要在 TROUBLESHOOTING 里加一条。

### 条件保护

目标平台不匹配时**编译期明确失败并指出行号**，禁止静默降级：

```cos
#%asm = arm64 (clobber: x0, memory)
#asm
{
    mov x0, #0
}
```

在 x86_64 上编译这份文件，报：`asm block at line 12 requires arm64, current target is x86_64`。

- 不允许"不支持就跳过这段"。要么编过，要么编不过。
- 不需要用户手写 `#if arch`；架构字段本身就是判据。

### clobber 列表强制

clobber 写在声明行里，与其他属性同处：

```cos
#%asm = x86_64 (clobber: rax, rcx, memory)
#asm
{
    ...
}
```

- 不写 `clobber` → 编译期报错。
- 声明不全 → 编译器不会替你检查（这是实验性支持的一部分代价），但漏声明会给出 warning。
- `memory` 必须显式写，不能省略。
- 空体也要写：`#%asm = x86_64 (clobber: memory)`。

### 不承诺密码学安全

- 汇编块里实现的任何加密原语，**不享受恒定时间保证**。
- 编译器不保证寄存器分配、不保证不插入额外指令、不保证不重排。
- 文档中所有"密码学不安全"的说明，对汇编块同样适用，且更强。

### 明确的非目标

v6 的汇编支持**不做**这些：

- 不提供寄存器变量绑定语法
- 不做跨架构抽象（x86 的写法不能移植到 ARM）
- 不保证优化器不会围绕汇编块做手脚
- 不为汇编块提供调试符号

## 四、内存安全与连续分配

### 先说清楚能保证什么、不能保证什么

「每个函数都申请到连续内存」——这句要拆成三层，只有前两层是真的能承诺的：

| 诉求 | 能不能 | 怎么做到 |
|---|---|---|
| **单次分配本身是连续的** | 能，无条件 | 任何分配器都这样，没意义 |
| **同一作用域内的连续分配地址相邻** | 能 | 每个块一个 arena，bump 分配 |
| **任意大小的分配永远不失败、永不碎裂** | **不能** | 物理上不可能。arena 用尽就要换新 arena |

最后一条必须说死，否则就是在画饼。任何声称「永不碎片」的分配器，实际做的都是「换一块新内存」——那不过是把碎片换成了大块闲置。区别只在于换得划不划算。

### 做法：每个块一个 arena

本语言有一个别人没有的条件：**没有指针、没有别名、按值复制**。这意味着对象的地址对用户不可见，运行时**有权移动对象**。这是 arena 方案能成立的根本原因——在 C 里做不到，因为用户代码手里握着地址。

```
块进入 ───→ 分配一个 arena（例如 64 KiB 连续页）
              │
              ├─ 块内每次分配：bump 指针上移，零碎片
              │
块退出 ───→ 整块 arena 一次性释放，O(1)
```

规则：

- 每个 `start` 块（含 `if` / `while` 的作用域）拥有一个 arena，线性递增分配。
- **块内分配一定是连续的**：同一 arena 内先后分配的对象地址单调递增、彼此相邻。
- 块退出时 arena 整块归还，**不做逐个 free**。这就是为什么块退出比 refcount 归零还快。
- arena 用尽时开一个新 arena 链在后面，容量不够只会导致多个 arena，**不会导致失败**（除非真的没内存了，那就是 OOM，正常报错）。

### 逃逸对象要提升

arena 整块释放有个前提：块内的东西块外不用。所以必须有「提升」（promotion）：

```cos
#% 值要出块时，拷贝到父块 arena
push ({result} = {local_computed})
```

什么时候触发提升：

- `push` 到一个比当前块**寿命更长**的变量
- `father` 向下传递时的复制
- `print` / DLL 调用参数（只在调用期间有效，不提升，见下）

本语言没有闭包、没有引用传递、没有指针，所以**逃逸路径是有限且可枚举的**——不需要完整的逃逸分析，只需要在赋值语句上判断目标变量的作用域深度。这是「按值复制」带来的便宜。

提升的开销是**一次 memcpy**，不是重新计算。对象大小已知，拷贝是线性的。

### 三档分配区域

| 区域 | 寿命 | 是否移动 | 用途 |
|---|---|---|---|
| **块 arena** | 块退出 | 可移动（只在安全点） | 绝大多数临时值 |
| **提升区** | 进程 | 可移动（只在安全点） | 出块的值、全局状态 |
| **钉住区** | 进程 / 手动 | **永不移动** | 交给 DLL 的缓冲区 |

钉住区就是 `gc_pin` 的物理实现：pin 不只是「不让回收」，而是**把对象搬到永不移动的区域并锁住地址**。这样 `PlaySoundA` 拿着的那块内存不会被 arena 回收，也不会被压缩搬走。

> 所以 `gc_pin` 的代价是双份：一次拷贝，以及失去后续压缩的收益。它只应该用在真正的异步边界上。

### 什么时候允许移动

移动对象有前提：**没有任何执行中的代码握着地址**。本语言里只有两种地址持有者：

1. **运行时的变量表**——它存的是对象引用，不是裸地址，移动时统一更新。
2. **外部 DLL**——它存的可能就是裸地址，**无法更新**。

所以移动只允许在**安全点**发生：

- 块退出时（arena 整块归还，不涉及移动）
- `The_world (force)` 内部（唯一显式的压缩点）
- 不发生在：DLL 调用期间、`lock` 临界区内、`nuclear_reactor` 链执行期间

这条「钉住区永不移动」的规则，是内存安全里最容易被忽略的一环，也是最容易出诡异 bug 的地方。

### 和引用计数的关系

两者不冲突，各管一段：

| | 回答什么 | 代价 |
|---|---|---|
| **arena** | 内存在**哪里**、什么时候**整块**释放 | O(1)，与对象数无关 |
| **refcount** | 这块内存**还能不能用**（跨 arena 的存活判定） | O(1) 每次赋值 |

`The_world (force)` 之所以便宜，就是因为大部分块内对象已经随 arena 整体归还了，force 只需要处理**提升区里计数归零**的那部分。

### 不承诺的部分

- **不承诺 O(1) 的最坏分配延迟**：arena 用尽时开新 arena 要申请系统内存，那一下是慢的。
- **不承诺堆碎片为零**：arena 之间会有空闲。但碎片被限制在「最多每块一个未用尾部」，不会随分配次数增长。
- **不承诺内存布局可预测**：压缩可能在安全点发生，地址会变。要稳定地址就用 `gc_pin`。
- **不承诺峰值内存最小**：arena 按整块预留，短命程序可能更浪费。要精确就用 `#gc = none` 测峰值。

## 五、支持等级

v6 起，文档和 README 明确标注每项能力的等级。

| 等级 | 含义 | 举例 |
|---|---|---|
| **稳定** | 承诺跨版本兼容，破坏性变更走主版本号 | 基本语法、`math_run`、数组、矩阵、位运算、并发组件、DLL 组件、`#gc = semi`、块内连续分配 |
| **实验性** | 可能在任何版本改变或移除 | `#asm` 内联汇编、`#gc = mark`、`gc_pin` 的嵌套语义、安全点压缩的触发时机 |
| **不承诺** | 明确说明不提供保证 | 密码学安全与恒定时间、汇编块的优化器行为、`bigint` 之外的任意精度、并发是模拟而非并行、全局零碎片、固定内存布局 |

**这条要写进 README 的"已知限制"表旁边**，让读者一眼看到边界在哪。

## 六、迁移影响

从 v5 升到 v6，需要动的只有两类程序：

1. **用了 `#pe`** —— 删掉。它从来没工作过。
2. **把缓冲区交给异步外部库** —— 加 `gc_pin` / `gc_unpin`。

其余程序不需要改。默认 `semi` 对行为透明。

## 七、实施顺序

```
1  移除 #pe，加编译错误与文档说明
2  #gc = none / semi 落地，semi 用 refcount
3  gc_pin / gc_unpin + DLL 边界测试用例（PlaySoundA SND_MEMORY）
4  The_world (stop / force / start)：停表深度、嵌套、跨块清零
5  #gc = mark，作为 refcount 的交叉验证工具
6  #asm 最小实现：标签式声明 + x86_64 单架构，三条规范全部编译期强制
7  支持等级标注写进 README 与语法参考
```

第 4 步紧跟 pin/unpin，因为两者共用同一张「对象不可回收」标记；先有手动干预，才能在 mark 档里造出便于观察的停顿点。第 5 步放在第 6 步之前，因为 `mark` 能用来验证 `semi`；先有验证手段，再做实验性功能。

## 附：为什么不做追踪式 GC

有人会问，为什么不直接上标记-清除或分代。

答案在上面已经写了：**这门语言没有别名**。

```cos
array a = [1, 2, 3]
array b = a          ← b 是 a 的副本，不是引用
```

`a` 改了不影响 `b`。没有指针、没有引用传递、没有闭包捕获、没有循环结构——**引用图必然是树**。

树上做引用计数不需要处理循环，也就不需要追踪。引入标记-清除只会带来 STW 停顿，换不到任何东西。

`mark` 档保留的唯一理由是当验证器用，不是当默认。
